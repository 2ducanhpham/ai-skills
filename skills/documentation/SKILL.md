# Technical Documentation

## Workflow
1. Identify the intended audience and documentation purpose.
2. Verify all statements against source code, configuration, or approved decisions.
3. Explain setup, architecture, workflows, interfaces, and operational procedures as relevant.
4. Include prerequisites, examples, failure modes, and troubleshooting.
5. Keep documentation aligned with implementation and link related ADRs.

## Rules
- Never document an unverified behavior as fact.
- Mark assumptions and version-specific instructions.
- Do not include credentials, tokens, private customer data, or secrets.
- Prefer concise, task-oriented documentation.
- Update existing documentation rather than creating duplicates where possible.
