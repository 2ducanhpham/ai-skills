# UI/UX Design

## Workflow
1. Understand users, product goals, primary journeys, and constraints.
2. Inspect the current interface and shared design system.
3. Identify usability issues, hierarchy problems, inconsistent patterns, and accessibility gaps.
4. Propose flows and component-level specifications before implementation.
5. Consider loading, empty, error, success, offline, and permission states.
6. Validate responsive behavior, touch targets, typography, contrast, and platform consistency.
7. Define visual and functional acceptance criteria.

## Rules
- Do not invent product requirements.
- Prefer clarity and consistency over decoration.
- Reuse existing design tokens and components where appropriate.
- Do not change business logic.
- Do not implement before design/acceptance criteria are approved when approval is required.

## Output
UX findings, proposed flow, screen/component specs, state matrix, accessibility checks, acceptance criteria.
